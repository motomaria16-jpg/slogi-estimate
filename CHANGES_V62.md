# СЛОГИ v62 — HTTP API Геокодера

## Что изменено

- Определение координат по адресу больше не использует `ymaps.geocode()`.
- Основной маршрут: браузер → официальный HTTP API Геокодера Яндекс (`https://geocode-maps.yandex.ru/v1/`) → координаты → GeoJSON кластеров → название кластера.
- Тот же ключ может использоваться, если он привязан и к JavaScript API, и к API Геокодера.
- Добавлен резервный серверный маршрут Supabase Edge Function `geocode-address` на случай, если браузер заблокирует прямой HTTP-запрос из-за CORS.
- Ошибки геокодирования теперь выводятся точнее и также пишутся в Console с префиксом `[СЛОГИ]`.
- Широта и долгота остаются только служебными полями и не показываются пользователю.

## Резервный серверный геокодер

Функция уже лежит в `supabase/functions/geocode-address/index.ts`.
Если прямой HTTP API работает в браузере, разворачивать её необязательно.
Если в Console появится CORS/Failed to fetch, разверните один раз:

```powershell
supabase functions deploy geocode-address --no-verify-jwt
```

Опционально ключ можно хранить в Supabase Secrets:

```powershell
supabase secrets set YANDEX_GEOCODER_API_KEY=ВАШ_КЛЮЧ
```

Если секрет не задан, функция принимает тот же ключ из клиентской конфигурации.

## Проверка

После запуска через `http://localhost:8000` введите адрес, например:

`Москва, Волоколамское шоссе, 95/2с8`

Ожидаемая цепочка:

`адрес → HTTP Геокодер → координаты → полигон → кластер → конкурентный анализ`.
