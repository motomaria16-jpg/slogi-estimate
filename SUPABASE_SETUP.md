# Подключение Supabase к сайту СЛОГИ

Проект и публичный ключ уже подключены в `cloud-sync.js`.

## 1. Выполните обновлённый SQL-скрипт

1. Откройте проект Supabase.
2. Перейдите в **SQL Editor → New query**.
3. Откройте файл `SUPABASE_SETUP.sql`.
4. Скопируйте его содержимое целиком в редактор.
5. Нажмите **Run**.

Повторный запуск безопасен: скрипт использует `create table if not exists` и пересоздаёт только политики доступа.

Скрипт создаёт и настраивает:

- `slogi_user_state` — адреса, паспорта, сметы и КП;
- `slogi_workspace_state` — задачи, платежи, согласования, версии, справочники, роли, журнал и настройки;
- `slogi_attachments` — метаданные файлов;
- закрытый Storage bucket `slogi-files`;
- Row Level Security, разрешающую пользователю доступ только к собственным данным.

Существующие записи и файлы не удаляются.

## 2. Настройте адрес сайта

В Supabase откройте **Authentication → URL Configuration**.

**Site URL**

```text
https://motomaria16-jpg.github.io/slogi-estimate/
```

**Redirect URLs**

```text
https://motomaria16-jpg.github.io/slogi-estimate/**
```

Для другого репозитория замените адрес на свой.

## 3. Опубликуйте файлы

Загрузите всё содержимое архива в корень репозитория с заменой старой версии. Особенно важны:

- `cloud-sync.js`;
- `professional-core.js`;
- `professional-shell.js`;
- `professional-pages.js`;
- `professional-ui.css`;
- новые HTML-страницы;
- `SUPABASE_SETUP.sql`.

## 4. Первый вход после обновления

1. Следуйте актуальному owner-approved runbook `docs/DEPLOYMENT_PASSWORD_GATE_V76_1_7.md`.
2. Откройте сайт на устройстве, где уже находятся актуальные объекты, и введите общий пароль в server-verified gate.
3. Убедитесь, что открылся выбранный существующий canonical workspace; новый workspace создаваться не должен.
4. Проверьте сохранение общего state и CAS revision.
5. На другом устройстве повторно введите общий пароль и подтвердите тот же workspace/state.

## 5. Проверка

Проверьте:

- отображение существующих объектов;
- сохранение статуса и ответственного в паспорте;
- создание задачи и платежа;
- создание версии документа и загрузку файла;
- создание версии сметы в разделе «Справочники»;
- восстановление объекта из корзины;
- синхронизацию после перезагрузки страницы.

## Как работает синхронизация

- изменения объектов и старых модулей синхронизируются через `slogi_user_state`;
- новые модули синхронизируются через `slogi_workspace_state`;
- файлы загружаются в закрытое хранилище;
- локальная копия остаётся доступной при кратковременной потере соединения;
- если таблица рабочего пространства ещё не создана, старые объекты продолжат синхронизироваться, но новые разделы останутся только на текущем устройстве до выполнения SQL-скрипта.
